# Device Checklists — Reserved Outlines

**Status:** Structure only. Existing organizational checklists will be supplied and incorporated later. These outlines do not replace the current approved procedures.

| Planned checklist | Sections to reserve |
| --- | --- |
| Device preparation | Asset identity, hardware condition, selected baseline, management model, software/peripherals, validation evidence, exceptions. |
| Device assignment and handoff | Assignment/ticket reference, intended user/department, asset and accessories, access verification, user orientation, acceptance, technician/date. |
| Recurring maintenance | Device and maintenance window, selected tasks, update/repair outcomes, restart state, unresolved issues, next action. |
| Device return and reassignment | Returned equipment, prior assignment, data-retention decisions, reset/reprovisioning path, new validation and assignment reference. |
| Device decommissioning | Asset identity, disposition decision, data handling, applicable management records, sanitization evidence where required, final verification and sign-off. |

Use blank templates in source control. Completed forms and device/user reports belong in the approved asset or ticketing system. Keep links or run identifiers connecting a checklist to its validation evidence; a generated report should support human sign-off rather than impersonate it.

When the existing checklists arrive, map their fields to these lifecycle stages, retain required approvals and evidence, and consolidate duplicate data entry.
