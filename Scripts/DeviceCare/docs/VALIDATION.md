# Validation contract — DTO DeviceCare 0.1.0

A successful test must identify an exact commit and runner. Local Python tests check package determinism, archive inventory, injection of unwanted files, manifest tamper, and the independent DTO identity boundary. Windows PowerShell scripts exercise synthetic provider outcomes and a separate native read-only collection mode. Source presence alone does not mean the native mode was executed.

Native mode on a Windows CI runner queries the OS and system disk without setting values or starting maintenance operations. It does not replace tests on a physical Windows 11 machine, high-contrast/keyboard/Narrator review, full security baseline, or any installer/upgrade/uninstall/restoration acceptance. The simplified reports are not a diagnostic certification.

Prior broader application tests remain historical and may include failing cases. They are never added to this DTO test total, promoted from another commit, or used to call the new preview ready.

Per-call CIM operation timeouts are not guaranteed whole-process deadlines. A restrictive machine policy, broken provider, wrong architecture, unusual disk state, or permissions can produce Unknown. No attempt to override the managed host is made.
